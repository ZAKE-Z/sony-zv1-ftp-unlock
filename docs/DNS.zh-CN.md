# FTP 域名与 Wi-Fi DNS

ZV-1 2.01 缺少当前 FTP 客户端 `getaddrinfo` 所需的 NSS DNS 后端。仅在 `/etc/resolv.conf` 中写入有效 DNS 地址仍不足以解析：持有者相机的原生探针无法加载 `libnss_dns.so.2`。a7C 2.00 包含该模块，且两机的 libc、libresolv 逐字节相同。

第 1 步现从 a7C **2.00** 的 `nflasha7` 分区提取 `/lib/libnss_dns-2.11.2.so`，在本地输出为 `assets/libnss_dns.so.2`。第 2 步安装到 `/usr/lib/`，核验基础库哈希，并用新的原生进程确认能够加载模块及找到 DNS 后端入口。修改后重启，避免主进程保留此前的模块加载失败缓存。

接入点页面原本就有 DNS 控件及相应的编辑、保存、导航代码。第 2 步在 `viewUnified4.so` 启用这条原生分支，并保留既有字符提交保护。机内自动 IP 沿用原生自动 DNS 行为，手动 IP 页面可设置主／备用 DNS；并未增加自动 IP 时独立指定手动 DNS 的功能。安装器不写 DNS 地址、SSID、密码或 IP 模式。

## 旧版升级

保留 `firmware/` 中指定的 a7 III 4.01、a7C 2.00 Windows 原包，重新运行 **1 → 2**。已知旧版 FTP 安装只需增加四字节界面修改和缺少的库，保留已有 FTP 服务器配置。需要修改服务器信息时才运行第 3 步；没有独立 DNS 配置脚本。

中英文根目录 CMD 编号保持：1 提取、2 解锁、3 写 FTP 配置、4 还原、5 修改报告版本号。

## 还原与验证范围

第 4 步同时识别上一版和本次 DNS 版：恢复原版 viewUnified4、移除哈希匹配的 DNS 模块及其他新增库，并清除 FTP 配置。保留 Wi-Fi 设置，包括用户输入的 DNS 值；仍不保证彻底恢复出厂状态。

**2026-10-17** 已在重启后核验文件哈希、FTP 配置未变、自动 IP／DNS 状态和原生模块加载。随后请持有者查看 DNS 两栏并用原 FTP 域名连接、传一张照片，持有者确认成功。该结果只覆盖当前相机和网络，不代表所有解析器、域名、路由器或手动 DNS 编辑组合均已验证。合并后的全新安装及扩展还原有离线测试，但没有分别在刚重置的相机上重新完整执行。

安装器的模块加载检查本身不测试 DHCP 下发、实际 DNS 查询或 FTP 连接。若域名仍失败，请保留具体提示，可用第 2 步 `--check`／`--verify` 只读检查；不要公开完整私人日志、Wi-Fi／FTP 密码或固件二进制。

## 文件

来源及哈希见 `resources/firmware_sources.json`、`resources/catalog.json`。仓库不分发 DNS 模块。自有 ARM 工具的源代码在 `scripts/native/`，采用 ARM Linux EABI／软浮点及相机旧 libc ABI，以 Zig 0.13.0 构建；使用安装包不需要编译器。
