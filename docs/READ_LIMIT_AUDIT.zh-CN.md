# 文件回读上限检查

本次为本地代码与资源检查，不是实机测试。已检查四种操作和辅助读取脚本。

| 读取对象 | 上限 | 检查结果 |
| --- | --- | --- |
| 解锁／还原：完整系统库 | 64 MiB | 已捕获的受支持系统库均小于上限 |
| 上传的补丁／探针工具 | 实际文件大小 + 1024 字节 | 随上传数据计算，不使用固定 64 KiB 上限 |
| 还原：五个新增依赖库 | 1 MiB | 最大库为 364820 字节，小于上限 |
| 配置：加密工具 | 文件实际大小 + 1024 字节 | 重建后的工具为 4636 字节，核验长度与哈希 |
| 配置：密文批次 | 2048 字节 | 预期输出 1024 字节，仍核验最终准确长度 |
| 报告版本记录 | 4096 字节 | 实际记录 2 字节，并检查长度 |
| 固件版本字符串 | 65536 字节 | 是很短的固件标识，不是工具文件 |
| 旧 MWF 辅助诊断 | 2 MiB | 已保存的 libMWF.so 均在上限内；该诊断不是安装入口 |
| 本地固件提取 | 无 USB 捕获上限 | 4 MiB 是分块计算哈希的块大小，不是完整文件上限 |

当前受支持资源未发现其他“工具文件超过固定读取上限”的同类问题。未知／更大的资源仍受机型、长度和哈希检查限制，不会自动放宽。新固件版本需要重新检查；接收适配器继续限制总量，不丢弃多余数据掩盖问题。

详细尺寸记录见 `../resources/read_limit_audit.json`。这一检查不等于已完成修正后的机内配置写入实测。
